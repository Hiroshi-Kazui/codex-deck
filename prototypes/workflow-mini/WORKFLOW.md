# 最小開発ワークフロー試作

この文書を読むメインエージェントが指揮する。ユーザーからの試作実行依頼に基づき、内蔵のサブエージェント機能で以下を実行する。

## 対象と役割

- 対象はこのフォルダの小さな試験用関数のみ。アプリ実装の M0〜M6 は対象外。
- メイン: 指示、実測テスト、判定、差し戻し、記録。実装者の自己申告で合格にしない。
- 実装者1体: `acceptance.md` に従い `clamp.mjs` だけを実装・修正する。
- 独立レビュワー1体: 実装と受け入れ条件を直接読み、テストを実行して判定する。ファイルは変更しない。
- 子から孫を起動しない。書き手は常に実装者1体。レビュー中は実装を停止する。
- 今回はモデルを親から継承する。Sol/Astraの役割別配分はこの試作の検証対象に含めない。
- CLI の再起動や外部モデル呼び出し用プログラムは使わず、この会話に提供される委任ツールを使う。

## 通常の手順

1. メインが実装者を起動し、対象ファイル・受け入れ条件・検証コマンドを渡す。
2. 実装完了後、メインが `node --test prototypes/workflow-mini/clamp.test.mjs` を実行する。
3. テスト失敗なら実装者へ差し戻す。成功なら、実装者とは別のレビュワーを起動する。
4. レビュワーは `status: PASS|FAIL`、条件IDごとの判定と証拠、blocking一覧を返す。
5. FAILならメインが指摘を元の実装者へ追加指示し、2へ戻る。レビュワーへの再指示は修正完了後に行う。
6. 全テスト成功かつ全条件充足かつblockingゼロで合格。修正は最大2回。上限・権限不足・不明な結果では未完了として停止する。
7. メインが `RESULT.md` に、実際のエージェントID、判定、検証結果、残る制限を記録する。未実行を成功と書かない。

## この試作だけの不具合注入試験

通常の初回合格後、差し戻し経路を確実に実測する。

1. メインが試験用 `clamp.mjs` にだけ「上限超過時に上限でなく下限を返す」不具合を入れる。変更内容を記録する。
2. 独立レビュワーに再レビューを指示する。期待する判定を強制せず、実コード・実テストで判定させる。
3. 実際のFAILと再現証拠を受け取り、元の実装者へFIXを指示する。
4. メインの再テストと独立レビュワーの再レビューで合格を確認する。

これは試作の故障注入であり、通常開発で意図的に不具合を作る手順ではない。FAILは実際の不具合と失敗テストに基づくものだけを記録する。

## 公式資料との対応

- [Subagents](https://developers.openai.com/es-419/docs/agent-configuration/subagents): メインによる委任・追加指示・結果回収、限定した役割、書き込み競合への注意、モデルと権限の継承を確認。現在の会話では `spawn_agent` と `followup_task` を使う。
- [AGENTS.md](https://developers.openai.com/es-419/docs/agent-configuration/agents-md): プロジェクト指示の適用範囲を確認。この試作はユーザーの明示した「サブエージェントの実装・レビュー・FIXのワークフローを試作する」依頼に従う。実装者・レビュワーは追加委任しない。
- 元のcockpitの `.claude/commands/cockpit-build.md` と `docs/harness/README.md`: メインが指揮する構造を参照。今回は最小試作のためレビュワーは1体とし、4観点レビューや本番の移行は未検証。

再実行の依頼例: 「prototypes/workflow-mini/WORKFLOW.md に従って、サブエージェントで試作を実行してください」。既存の記録は消さず、新しい実行分を追記する。

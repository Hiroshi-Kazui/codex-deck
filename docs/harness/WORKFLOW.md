# codex-deck 開発ワークフロー

この定義書に従って指揮するのは、ユーザーと対話しているメインエージェントである。
内蔵サブエージェントへ実装・独立レビューを委任し、実測検証・FIX・再レビューを回す。
外部のNode.jsプログラムによるCodex CLIの入れ子起動は、このワークフローの起動方法ではない。

## 起動と対象

「このワークフローでM0-01を実装」「M0まで進める」「M6まで実装」のような依頼をメインが受ける。スキル名やCLIコマンドの入力は不要。
対象が文脈で確定していれば再確認しない。ハーネスの作成・レビュー依頼はアプリ実装開始の指示に読み替えない。
範囲の指定がないアプリ実装依頼では、依存を満たす最初の未完了タスクを1件扱う。明示された複数タスクの範囲では合格後に順番に続行し、各タスク間で承認を取り直さない。

## 着手前

1. `AGENTS.md`、`docs/spec/product.md`、該当ADR、`milestones/tasks.json` の対象タスク、そのreads、直近の記録を読む。
2. tasks.jsonのID・依存・scope・criteria・checksを作業の正とする。依存未合格なら先へ進まない。
3. 書き込みを行う実装者が他に動いていないことを確認する。旧CLIランナーの生存・子孫終了未確認があれば、アプリへの書き込みは開始しない。新方式に変えただけで旧cleanupRequiredを解除しない。
4. 内蔵の起動・追加指示・状態確認ツールの存在を確認する。現セッションでは `spawn_agent`、`followup_task`、`list_agents`、`wait_agent`。UIや別CLIで代理起動しない。
5. `.harness/native/<run-id>/` に対象・許可する変更範囲・条件・作業前の全ソースファイル一覧とSHA-256・開始日時を記録する。未追跡ファイルも含める。旧 `.harness/state.json` は再利用しない。

## 役割と並行数

役割の指示は [roles.md](roles.md)、合格判定は [review-rubric.md](review-rubric.md)。

| 役割 | モデル / effort | 責務 |
|---|---|---|
| メイン | 現在の会話のモデル | 割当て、検証実行、結果判定、FIX集約、記録 |
| implementer | gpt-5.6-sol / high | 割り当てた1タスクの実装・修正 |
| code / architect / usability / requirements | 各gpt-5.6-sol / high | 独立した4観点のレビュー |
| critical-reviewer | gpt-6-astra / high | criticalタスクの追加レビュー |
| diagnostician | gpt-6-astra / high | 2回の不合格後の原因診断、1回限り |

起動時にモデル・effortを明示し、明示指定する場合は現行APIに合わせ `fork_turns: none` または必要な文脈に限った件数を指定する。ツールで指定できない、またはモデルが使えない場合は未実施として理由を報告する。代替モデルへの暗黙切替は禁止。
このセッションではメインを含め4枠。実行中の実装者とレビューを重ねず、完了した実装者にはレビュー終了まで追加作業を送らない。4観点は最大3体ずつ等のバッチで行う。枠が足りなければ順番に行い、レビューの省略で対応しない。
全レビューが同一の変更を読むまで、メインも実装者も対象ソースを変更しない。

## 実装 → 検証 → レビュー → FIX

1. **IMPLEMENT**: メインが新しい実装者へ対象タスクJSON、仕様/ADRの参照、変更可能ファイル、受け入れ条件、検証コマンドを渡す。実装者は完了・blocked・変更ファイル・検証・引継ぎを返す。
2. **変更範囲の実測**: メインは実装前後の全ソースファイル一覧とSHA-256を比較し、追加・変更・削除を確認する。未追跡ファイルも対象にし、実装者の申告した一覧だけを根拠にしない。対象タスクで許可された範囲とAGENTS.mdの保護対象に照合する。無断の範囲外変更や保護対象の変更があれば検証・合格判定を止め、差分と所有者を記録して意図的に解決する。自動ロールバックやユーザーデータの削除はしない。
3. **検証**: メインがtasks.jsonのchecksを実行し、終了コード・出力・実行日時・ソース指紋を保存する。検証ログを含む合格根拠のファイルは `.harness/evidence/<task>/` に保存し、タスク・check・レビューとの対応、一覧、SHA-256を別途記録する。未存在コマンド、失敗、skipで満たされない条件を合格にしない。検証がソースを書き換えた場合も未検証扱いとする。
4. **失敗時**: コマンド失敗は実装者へ直接FIX。成功なら4観点の独立レビューへ進む。critical:trueなら追加のAstraレビューも必要。
5. **REVIEW**: 実装者とは別スレッドで起動。受け入れ条件・ファイル・実測ログを渡し、実ファイルの読取りを要求する。メインの検証を盲信させず、必要なら未解決事項を再現する限定検証を行わせる。同じ合格済みテストを理由なく繰り返さない。レビューと診断はソースを変更しない。メインは各役割の終了後も実測指紋を照合する。
6. **判定**: 必須チェック成功、全条件充足、必要な全レビューPASS、blockingゼロの場合だけ合格。判定直前にも変更範囲と全ソース指紋、必要な証拠ファイルの存在・内容・SHA-256を照合する。証拠の変更・削除は対応する検証を失効させる。全員の結果が揃う前にFIXや次タスクへ進まない。未回答・壊れた結果・条件の欠落・PASSとblockingの矛盾は合格不可。
7. **FIX**: 不合格の指摘を根拠付きで集約し、元の実装者に `followup_task` で渡す。実装者が指摘を無視することは禁止。指摘への反論があれば証拠をレビュワーへ返し、解決しなければ未解決として停止する。
8. 修正後は変更範囲の実測、必要なchecksと全レビューを再実施する。レビュー中にソースや証拠の変更を検出した場合、変更前の証拠を使わない。
9. 初回＋FIX最大3回。2回不合格になった時点でAstra診断を1回行い、その指示を渡した新しい実装者へ切り替える。診断は条件変更や合格認定をしない。上限後は停止して未解決事項を報告する。

メインはアプリコードの代筆でレビュー指摘を片付けない。ハーネス定義の修正は、アプリ実装とは別の依頼として扱う。

## 実機ゲート・停止・再開

- M0-03の実Codex対話・承認往復等を満たすまでM1へ進まない。M2-01のIME、M6-01のWindows実機確認も模擬結果で代用しない。
- 実機証拠は `.harness/evidence/<task>/`。日時・環境・CLI版・結果・関連ログを保存する。できなければ未検証として停止する。
- ユーザーが停止を指示したら、実行中の子に停止を伝え、必要なら内蔵割込みツールを使う。エージェントの停止と、その子が起動したOSプロセスの終了は別々に確認する。
- 中断、モデル利用不可、権限不足、仕様判断待ちでは原因・未完了作業・子の状態を記録する。ネットワーク制限をサブエージェントの無条件な利用不能と混同しない。子のシェルや実機の制約は実測に従う。
- 再開時はログと子の状態、ソース指紋を確認する。ソース変更があれば合格証拠を失効させ再検証・再レビュー。変更がなければ完了した実装を無意味に繰り返さない。
- 再開時には必要な証拠ファイルの一覧とSHA-256も照合する。欠落や内容変更があれば対応する検証を失効させ、再検証・再レビューする。
- 環境が提供しない自動タイマーや強制停止を保証しない。上限回数をメインが管理し、ユーザー停止を優先する。
- 長い作業中は、完了したこと・現在の作業・障害・次の手順を短く定期的に伝える。判断が本当に必要な場合も、安全に進められる独立作業を先に済ませ、既に与えられた承認を取り直さない。

## 記録

`.harness/native/<run-id>/` にメインが追記で記録する: 対象、実装/レビューのエージェントID、指定モデル、各指示、実測した追加・変更・削除、checksの出力と終了コード、役割別verdict、FIX内容、判定、残るfollowup。
指紋は作業対象ソース・条件・テストを含むファイル一覧とSHA-256。未追跡ファイルを含め、`.git`、`.harness`、依存物、ビルド出力等だけを除外する。既存 `tools/harness/storage.mjs` のsnapshot純粋補助処理を使ってもよいが、CLIランナーは起動しない。
`.harness/evidence/<task>/` のうち判定に使う実機証拠・検証ログ等は、ソース指紋とは別の一覧とSHA-256でタスク・check・レビューに結び付ける。変動する `.harness/native/<run-id>/` の進行記録は、この証拠指紋に含めない。
新しいファイルも検出できるよう一覧を取り直す。過去の記録やユーザー変更は削除しない。
全員PASSでも未解消のfollowupは保存する。指定範囲の合格または停止時に、実測結果・未検証・残課題を報告する。

この文書は人間向けの操作マニュアルではなく、メインが実行する指示書である。独自のモデル呼び出しプログラムをユーザーに起動させることを前提にしない。
